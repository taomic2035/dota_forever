## 子系统交付

### 1. 操控与 UX/HUD(本版主线)

完整的玩家操作体系,核心可玩性与游戏手感全面提升:

- **单位选择体系** — 左键选中 + 拖框多选 + 控制组(1–6 绑定/选择)+ F1/F2/F3 快速选英雄/信使/全部;敌红/友绿/中立黄悬停轮廓(pre-click 预判)、选中高亮环。
- **选中信息卡** — 选中非受控单位时左侧弹卡,含属性读数(攻击/护甲/魔抗/移速/攻击距离)与 buff/debuff 状态行;`statusChips` 纯函数同源于 HUD 与信息卡。
- **指令卡(3×3)** — 移动/攻击移动/停止/守住/选英雄/选信使/选全部/守护符/商店;`ACTION_LABEL` 中文。
- **完整改键** — 16 个动作可重绑;`buildKeyTranslation` 规范键翻译;系统键(空格/Tab/P/Esc/=/-)保护防修饰键冲突。
- **施法/引导进度条** — 自己 + 敌方(可预判打断),施法青 `#46d0ff` / 引导金 `#ffc23a`,2D/3D 共用 `castBar`。
- **公屏播报** — 一血(红)/连杀里程碑(streak≥3,金)中央大字,弹入淡出 + 戏剧 stinger。
- **危险反馈** — 血 <35% 全屏红光暗角(强度递增,<20% 脉动)+ 危险音脉冲;己方建筑被敌方英雄攻击 → 小地图 ping + 警报音(每建筑 6s 限频)。
- **商店系统** — 分类页签 + 搜索过滤(`buildShopVisibleItems`)+ 购买去向预览(`buildShopDestinationModel`,预测物品栏/背包/暂存/TP/拒绝,与真实 `buyItem` 路径分支对齐)+ 右键出售(50% 返还)+ toast。
- **自动攻击** Never/Standard/Always(默认保护正补);**观战变速** `=`/`-`(5 档吸附,看 AI 局快进/慢放团战)。
- **宏观信息层** — 顶栏 Roshan/Boss 重生、Glyph 冷却、神符刷新倒计时;Alt 显示防御塔攻击范围(纯展示零机制风险)。
- **手感修复** — HUD 全面 `mousedown`(杜绝每帧 `innerHTML` 重建丢点击)、镜头跟随英雄、3D 补刀/反补飘字、HUD 血蓝/护甲/魔抗显著化、全 UI 中文化 + 音量控制、开局操作引导面板 + 原创背景音乐。

**工程要点**:输入架构统一在 `InputManager`(规范键翻译 + smartHold + `CommandMode` 状态机,支持 normal/quick/smart 三种施法模式);HUD 每帧 `innerHTML` 覆写改用 `mousedown` + data 属性委托;施法追踪 `castBarInfo` 维护 per-unit 起止时刻(0.02s 阈值判新一次施法)。

### 2. 玩法机制深度

- **全 112 英雄阿哈利姆神杖** — 数值轴 `scepter` + 行为轴 `hasScepter` + 被动轴 `scepterPassive`;`scepterCoverage` 守卫。
- **专属回城卷轴槽**(第 7 格,T)+ **背包栏**(后备 3 格,无加成,移入物品栏 6s 就绪延迟)。
- **信使 courier** — 每队一只,自动投送储藏物品;可击杀(赏金 60,泉水 35s 重生);英雄离泉水 >1500 才派信使。
- **防御符文 Glyph** — 己方建筑短时免伤 + 长冷却;玩家手动(G)或 AI 自动护塔(建筑被 dive 时)。
- **后门保护 Backdoor** — `BACKDOOR_RADIUS=900` 内无敌方小兵时,T3/T4/兵营/主基地受击 ×0.4 伤害 + 6%/s 回血(T1/T2 仍可后门拆)。
- **防御塔 Pierce + 连击递增** — `tower` 攻击类型对英雄 0.5×(对兵/建筑不变);同目标 +20%/击,封顶 ×1.5。经 batchsim 实测:无封顶时永夜 90min 无胜者,封顶后 8/8 决胜(44–79min)。
- **核心物品机制** — 血石充能(敌死 1200 内 +1,缩短重生)、净魂之刃 8 次充能、动力之靴 str/agi/int 三属性切换、寒冰守卫减速光环、巨人之心脱战回血(修 `nextTickAt` 未初始化 bug)、Break 破坏框架 + 静默之刃。
- **首波兵线 0:00 出兵**(经典号角,波次相位 = f(绝对时间))、堆野机制确认、cyclone/banish 升空(untargetable)打断施法。
- **bot 阵容种子随机**(全 112 池无重复,`?seed` 可复现)。
- **技能预览形状契约** — `AbilityDef.aoeRadius?: number[]` / `lineWidth?: number`,46 项填充;preview-only(sim 不读)→ 零行为变更,逐步磨锐预览。击杀协助归属(`hero_kill.assists`)。

### 3. 2D/3D 渲染器与表现层

**Opus 负责渲染器引擎 + 渲染器对等**:

- **共享纯函数杜绝奇偶漂移** — `castBar`(施法/引导条)、`fogShared`+`fog3d`(世界空间迷雾纱罩,`FOG_MESH_N=100` 贴地形高度,`FOG_LIFT=6` 防 z-fighting,DataTexture 驱动 vision)、`healthBar`(250/1000 血条刻度,经典绝对血量视读)、`statusPips`(状态点条)、HUD 径向冷却扫描(conic-gradient 时钟楔形)。
- **P0 迷雾门控修复**(关乎公平性)— 此前 3D 对移动单位无视野判定,雾中敌方英雄/小兵/眼全泄露;现 `visible = viewerTeam===null || 同队 || isVisibleTo`,雾中单位隐藏 + 不画血条 + 跳过动画 CPU。实测 13 个雾中敌人全隐藏。
- **`speed=NaN` 守卫** — `?speed` 非法值会令 `GameLoop` acc 永久 NaN → 模拟冻结 → 3D 坐标全 NaN;`main.ts` 加 `isFinite && >0` 守卫回落 1。
- **英雄体型层级**(×1.5)、渐变天空穹顶(BackSide 大球竖直渐变 + 昼夜联动,预留 HDRI 接缝)、场景距离雾。

**集成 Codex V4–V24 表现层**(Codex 资产/模型,Opus 评审 + 集成 + 动效驱动):

- **V4 地形真实感** — `terrain3d.ts` 重写(648 行,~42 层:树墙/草丛/河道/崖壁/栅栏/地标环/天空穹顶);`updateTerrainRuntimeMotion` 逐帧驱动河流/浪花/芦苇。
- **V5 可读性契约** — 英雄 first-read(冠饰/武器线/背影/施法焦点)+ 兵线单位辨识,解决「英雄太小没和小兵区分」。
- **V3/V6–V9 资源 + 多层 FX** — 408 资源样本 material/detail 元数据;`Fx3D` 单球→ core/glow/accent/particle/trail 多层(火/冰/雷/毒/圣光/奥术);纯函数 `resourceMotion`/`fx3dVisual`。
- **V10–V17 运行时表现** — motion/surface/animation helper(optional consumption,目前仅 preview 层激活)。
- **V18/V22/V23 模型质量** — 箱体占位 → 对局镜头几何剖面(CapsuleGeometry/倒角 ExtrudeGeometry/曲面);`gameplayModelQuality` 契约按 play 视角(zoom 0.62 / 56° 俯角)解剖可读。

### 4. 音效与打击感

程序化 WebAudio,零样本无版权。`AudioDirector` +194 行(~100 → 322),12 个新方法:

- **打击感** — 补刀金币 ding(1180/1560Hz)+ 反补闷响(320Hz)、命中按伤害分层(清脆瞬态 + 低频闷击)。
- **施法音色按性质区分** — `representativeCastTag` 纯函数按 `TAG_PRIORITY` 选代表性标签,`castFor` 惰性构建 abilityKey→tag 全表;stun/nuke/heal/aoe/slow/ultimate 各异。
- **操控反馈闭环** — 移动/攻击/拒绝/物品使用音、低血双拍脉冲、建筑警报双音、公屏 stinger 和弦。
- **动态限幅器** — master → `DynamicsCompressor`(-14dB/ratio 6)→ destination,密集战斗防过载失真。
- **原创背景音乐** — A 小调失谐 pad(110/130.81/164.81/220Hz)+ 55Hz drone,暖色低通 + 慢速滤波 LFO,5s 渐入无缝循环。

### 5. 质量守卫与测试基建(741 → 1370,155 文件)

## 工程亮点

`★ 架构基座 ────────────────────────────────`
**共享纯函数是 2.1.0 的核心 foundation**。`castBarInfo` / `writeFogRGBA` / `healthBarTicks` / `statusChips` / `abilityPreviewShape` 这些跨 2D/3D、跨 sim/UI 的纯函数,把「视觉/判定逻辑」集中在一处、由两个渲染器共享消费。任何重复实现最终都会因一方改动而漂移 —— 奇偶问题的根治不是「两边各写一遍」,而是「一处写、两处读」。
`──────────────────────────────────────────`

- **3D 迷雾用世界空间 mesh 而非屏幕叠加** — 透视投影天然正确,贴合地形高度避免穿模。早期屏幕空间叠加的透视错误证明:架构决策必须与渲染管线思路对齐。
- **务实平衡靠 batchsim 闭环** — 塔伤连击递增封顶 ×1.5 不是拍脑袋,而是 8 种子实测「无封顶 → 攻坚僵局」后定的;决胜时长 44–79min 分布均衡。
- **预览契约 migration-safe** — `aoeRadius` 缺省回落 `DEFAULT_AREA_RADIUS=220`,wiring 零回归,可逐技能渐进填充。
- **运行时表现双轨制** — V10–V17 的 motion/surface helper 为 optional consumption(目前仅 preview 激活),预留游戏内逐帧消费的优化空间。

## 协作复盘:Opus↔Codex 同树并行

**模型**:同一 git 树并行 + 文件归属边界 + 纯函数契约 + settle 点全量验证。Opus 驻守渲染奇偶 / sim 忠实度 / 评审集成;Codex 负责多单位 / 输入 / UI 实现与 3D 资产。92 个提交、零文件冲突、main 始终可发布。

### 有效实践

1. **明确文件归属边界** — `input.ts`/`hud.ts`/`selection*.ts`/`commandCard.ts`/`shop*.ts` 归 Codex,`castBar`/`fogShared`/`healthBar`/`combat.ts` 归 Opus;共享文件用纯函数表达契约,双方读取而非编辑。10+ 并行提交零 merge 冲突。
2. **共享纯函数作为接口契约,而非共享数据结构** — AoE/line 预览:Opus 铺数据契约(`aoeRadius[]`/`lineWidth`/`targetMode:'line'`)+ 纯函数 `abilityPreviewShape`,Codex 在 `previewCast`/`previewItem` 消费。分钟级接通,避免冗余实现导致漂移。
3. **评审 → 交接 → 集成的流水,而非直接 merge** — Batch 4(选择/控制组):Opus 评审 Codex 成果、确认无 bug、列分工建议,再由 Opus 集成提交,建立干净基线。
4. **分钟级频繁小提交划清 delta** — 每个提交单一职责,评审者可快速校验意图,避免代码积压冲突。
5. **基础设施先于功能** — 缺 `three`/`@types/three` 致 tsc 报错 100+ 且 3D 测试全断;功能前先 `npm install` 补齐,确保全树干净可编译。
6. **后期演进到自治** — Codex 从「留未提交工作等 Opus 集成」演进到「自提交自推送」(shop 收尾),协作开销进一步下降;Opus 转为每个 settle 点全量验证 + 集成。

### 踩过的坑与教训

- **共享文件一旦双方编辑即陷「共享地狱」** → 从一开始就让一方维护数据铺垫(Opus)、另一方维护消费端(Codex),而非预期两边自由编辑。
- **「先读码再动手」两次避免坏改动** → 差距分析指向「魔免挡指向」与「旋风打断缺口」;读码发现旋风打断是真缺口(已修),但魔免挡指向在 `applyModifier` 已有完整拦截、再加 ability 层会误挡穿透技能(未改)。实施前过度评审 > 猜测或先改再测。
- **preview 路由 ≠ 游戏内质感** → V22/V23 英雄模型在 preview 下好看,但游戏内(zoom 0.62/56°)仍方块化;用户判的是游戏内。每个功能必须在真实玩法镜头下验收。
- **对抗式审查把噪声压成信号** → 合入 Codex shop 收尾时,17-agent 审查的 13 发现里 12 是「未测但代码正确」的误报,逐一读真实路径证伪,只剩 1 个真实覆盖缺口。没有这层验证会浪费精力去「修」本就正确的代码。
